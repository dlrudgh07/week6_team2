    권장 순서

    뒤 단계가 앞 단계에 기대는 순서입니다. 예를 들어 에디터 선택 상태를 약참조로 바꾸려면 약참조가 먼저 믿을 만해야 합니다.

    1. GUObjectArray를 free-list로 교체약참조와 InternalIndex 기반 캐시가 전부 여기에 기댑니다.B1
    2. Dirty 리스트 비우기, Destroy 지연 처리세션이 길수록 느려지는 문제와 Tick 중 삭제 크래시를 막습니다.B6 · B3 · R1
    3. 컴포넌트 등록 경로 통일SpawnActor, AddComponentByClass, PIE 복제가 같은 함수를 쓰게 합니다.B4 · R2 · R3
    4. 씬 로드 이름 매칭 확인 후 이름 규칙 수정먼저 실제로 씬을 열어 Transform이 적용되는지 확인합니다.B2
    5. 링크 에러 위험 제거, 빠른 정리정의 없는 선언, 로그 스팸, 데드코드를 치웁니다.B5 · C1 · C3
    6. 장기 과제프로퍼티 플래그, 직렬화 기반 복제, 컬링을 Runtime으로 이동, SceneProxy와 렌더 스레드 분리.R4 · R5 · R8 · R10

    URenderAsset

    UE에서는 UFont와 UMaterialInterface가 UObject를 바로 상속합니다. UStreamableRenderAsset은 Mesh와 Texture만 묶습니다. 여기서는 경로를 가진 에셋의 공통 부모로 쓰입니다.

    라이트

    UE는 ULightComponentBase → ULightComponent → ULocalLightComponent → UPointLightComponent → USpotLightComponent 순서입니다. UE의 ASpotLight는 라이트 컴포넌트가 Root이고, 빌보드는 에디터 전용 스프라이트입니다. 여기서는 Billboard가 Root입니다.

    파티클

    UE는 UParticleSystemComponent : UFXSystemComponent : UPrimitiveComponent이고, SubUV는 이미터 모듈입니다. Billboard 상속은 이 프로젝트 고유 설계입니다.

    머티리얼 인스턴스

    UE는 UMaterialInstance와 UMaterialInstanceDynamic을 별도 클래스로 둡니다. 여기서는 UMaterial의 bIsInstance와 Parent로 처리합니다.

    없는 게임플레이 프레임워크

    UEngine, UGameInstance, APawn, AController, AGameModeBase, ULocalPlayer, UInputComponent. 지금은 카메라가 FInputSystem을 직접 폴링합니다.

    GC 대신 명시적 delete

    UE는 UPROPERTY 참조 그래프와 GC로 수명을 관리하고, Destroy는 EndPlay 후 MarkAsGarbage를 거쳐 GC 때 해제합니다. 여기서는 DestroyActor가 즉시 delete합니다. 그래서 에디터의 생 포인터를 ResetSceneSelection()으로 직접 정리해야 합니다.

    World 소유자

    UE는 GEngine의 WorldList에 있는 FWorldContext가 World를 소유하고, World의 Outer는 UPackage입니다. 여기서는 FEditorApplication이 그 역할을 합니다.

    카메라

    UE의 카메라는 Level 안의 Actor입니다. 여기서는 Level 밖이라 저장과 Outliner에서 빠집니다. 의도된 설계로 보입니다.

    컴포넌트 등록

    UE의 RegisterComponent는 SceneProxy를 만들어 FScene에 넣습니다. 여기서는 UWorld::AddComponent로 BVH용 약참조 배열에 넣는 것이 전부입니다.

    네이밍

    기본 규칙은 잘 지키고 있습니다. 어긋나는 부분은 수정 목록의 정리 항목(C5 ~ C11)에 넣었습니다.

    잘 지키는 것

    • 접두사 U A F T E I, 전역 G (GUObjectArray), NAME_None
    • bool은 b, 파라미터는 In / Out, Super / ThisClass 별칭
    • 파일명은 접두사를 뗀 클래스명 (AActor ↔ Actor.h)
    • 폴더가 UE와 같음: GameFramework, Components, UObject, HAL, RHI, Misc, Templates, Camera, Particles
    • enum class + E 접두사, .clang-format (Allman, 탭)

    어긋나는 것 (요약)

    • 헝가리안 표기 mDatas, 소문자 멤버 model, mesh
    • 오타 DepthSteincil, Attatch
    • 기본 컴포넌트 이름에 접두사가 있기도 없기도 함
    • Orthogonal과 Orthographic, NearZ와 NearClipPlane 혼용
    • 클래스 이름 문자열 "AActor" vs "Object"
    • 파일명에 F 접두사 (FScene.h, FogSceneData.h)
    소스를 정적으로 읽고 작성했습니다. 빌드나 실행으로 확인하지 않았으며, "확인 필요" 표시 항목은 먼저 재현해 보는 것을 권합니다.
